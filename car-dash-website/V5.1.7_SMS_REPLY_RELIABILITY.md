# v5.1.7 — SMS Reply Reliability

This update fixes customer SMS replies not appearing in the Owner/Admin inbox.

## What changed

- Added a Twilio message-history sync fallback. The SMS Inbox now checks Twilio every 30 seconds and imports recent inbound replies even if the webhook was misconfigured or temporarily failed.
- Added an owner-only **Repair SMS Connection** button. It configures the current Messaging Service to POST inbound messages to `/api/sms/inbound` on the public site.
- Added connection-status reporting so the dashboard shows whether Twilio is actually pointing inbound SMS at this website.
- Improved webhook signature URL handling for Vercel/custom-domain proxy headers.
- Refactored inbound SMS storage so webhook-delivered and history-synced messages use the same deduplication/matching logic.
- Added an **Unmatched SMS replies** section. If a sender phone number does not match any booking, the message is saved instead of silently discarded.
- Messages are deduplicated by Twilio Message SID, so webhook delivery + history sync cannot create duplicates.

## Recommended deployment environment

- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_MESSAGING_SERVICE_SID`
- `NEXT_PUBLIC_SITE_URL=https://cardashdetailing.com`
- Optional: `TWILIO_INBOUND_WEBHOOK_URL=https://cardashdetailing.com/api/sms/inbound`

After deployment, open Owner Dashboard → SMS Inbox. If the connection banner is amber, click **Repair SMS Connection** once.
