# Car Dash Detailing v5.4.5 — Server-rendered website content

## What this fixes
Public pages no longer show the built-in fallback copy for a moment and then switch to the owner-edited database copy after JavaScript loads.

## What changed
- Added one server-side site-content loader (`src/lib/site-content.ts`).
- Current editable website content is loaded before the HTML is sent to the browser.
- The loader still falls back safely to `SITE_DEFAULTS` if the database is temporarily unavailable.
- React request memoization keeps repeated content reads in the same render from opening duplicate queries.
- `connection()` keeps owner-edited content request-time/dynamic instead of baking a stale database snapshot into a production build.
- Homepage content is passed into the interactive homepage as initial server data.
- Public hero copy is server-rendered.
- About and FAQ editable copy is server-rendered.
- Car, exterior, and interior pricing pages receive the current pricing config before hydration.
- Services/add-on pricing is server-rendered.
- The footer receives the current database blurb before first paint.
- Contact/booking receives the current pricing configuration before hydration, so package/add-on text and prices do not start from stale defaults.
- Owner editing APIs and dashboards remain unchanged.

## Result
On refresh or normal page navigation, the first visible text should already be the current version stored by Car Dash. There should no longer be a visible `old/default copy -> current copy` swap on the public website.
